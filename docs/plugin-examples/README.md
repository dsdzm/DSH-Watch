# 示例插件：连续执行（带对话预设）

`dsh-plugin-continuous.json` 是把 **dsh-purge Community** 的能力映射成这边
声明式插件的一份示例。它不能替代 dsh-purge —— 这两者的运行位置不一样，
能做的事也不一样。下面这张表说清楚差在哪。

## 为什么不能直接装 dsh-purge

`dsh-purge-community-*.tgz` 是 Cordis 的 npm 包，里面的入口是 `apply(ctx)`，
要 `ctx.fs`、`ctx.tools` 和 Node 运行时。这个 App 没有 Node，插件体系也不是
「跑一段代码」，而是「读一份声明」——**代码本身永远装不进来**。

但从 1.24.1-beta.2 起，直接选这个 `.tgz` 也不会停在「装不了」上了：
应用会把包里的源码当文本读一遍，把那些最终会写进系统提示的话抽出来，
做成一份**草稿**给你核对，确认后按声明式插件装上。

| 包里有什么 | 转译结果 |
|---|---|
| 大段提示词（中文密度高、有祈使句） | 最长那段 → `prompt.append` |
| 「短名字 + 一段正文」的对象列表 | 配成几条 `presets` |
| `ctx.tool(...)` / `ctx.fs` / 钩子 | 丢弃，核对页会写明丢了什么 |
| `autoApprove` 之类的权限字段 | 永远不转 —— 只能收紧，不能放宽 |

转译是启发式的，会认错（比如把一段日志当成提示词），所以它从不静默导入。
想精确控制的话，手写下面这种 JSON 仍然是最好的路。

## 能力对照

| dsh-purge 做的 | 这边 | 说明 |
|---|---|---|
| 破甲 / 减少确认 | **做不到** | 插件只能收紧权限，任何放宽审批的字段都会被拒收。替代方案见下 |
| 极简回复 | 内置 `dsh-whale`，默认开 | 不用插件也能用；想改语气就写 `prompt.append` |
| 结果裁剪 | 内置 `dsh-token-saver`，默认开 | 工具结果进上下文前折叠中段 |
| `preset install` | **`presets` 段**（schema 3 新增） | 插件带几条预设，在选择器里选 |
| boost 尾部锚点 | `prompt.append` | 拼在系统提示末尾，每轮都发 |
| `excludePresets` | 不需要 | 预设是「选中才生效」，没选就不注入，不存在要排除的全局注入 |
| 快照 / 回滚 | 删掉清单即可 | 插件本身就是一个 JSON 文件，没有要回滚的宿主状态 |

### 关于「减少确认」

dsh-purge 的卖点是放宽审批，让任务一路跑完。这边方向是反的：
**把会弹窗的工具整个关掉**（`tools.hide`），模型不会去调它，自然也不弹窗。

体验同样是「一路跑完」，代价从「危险命令可能被执行」变成「模型干不了这件事，
会直接告诉你」。手表上用户看不见键盘、也看不清一长串命令，
「看不懂就别让它跑」比「弹个窗让他点同意」更负责。

示例里**没有**写 `tools.hide`：它默认保留全部工具，只改说话方式。
要收紧就自己加，例如：

```json
"tools": { "hide": ["run_script", "cloud_build"] }
```

## 怎么用

1. 把 `dsh-plugin-continuous.json` 复制到手机 / 手表能选到的地方；
2. 设置 → 插件 → 导入 → 选择文件（或把内容复制到剪贴板再「从剪贴板粘贴」）；
3. 导入后插件是**关闭**状态，打开它；
4. 供应商 → 提示词 → 预设，会多出「连续执行」「只读审查」两条，副标题标着来源。

新建对话时会自动带上该预设的开场白，且只在**当前选中的预设**有 `opening` 时插入。

## 自己写一份

```json
{
  "schema": 3,
  "id": "dsh-plugin-你的标识",
  "name": "设置里显示的名字",
  "description": "一句话说明它改了什么",
  "prompt": { "append": "常驻追加的系统提示（可选）" },
  "presets": [
    {
      "id": "preset-1",
      "name": "预设名",
      "description": "选择器里的一句话说明",
      "systemPrompt": "选中后作为系统提示的主体",
      "opening": "新建对话时自动说的一句（可选）"
    }
  ]
}
```

硬性限制：

| 项 | 上限 |
|---|---|
| 一份清单 | 16 000 字符 |
| 一个插件 | 6 条预设 |
| 单条 `systemPrompt` | 2 000 字符 |
| 单条 `opening` | 600 字符（它是一条真实消息，会进上下文与导出） |
| `id` | 必须 `dsh-plugin-` 开头；预设 id 小写字母/数字/下划线/短横线，2–24 位 |

`opening` 会作为一条真实的 assistant 消息留在会话里 —— 所以它只在编程场景插入，
酒馆与写作的开场由角色卡 / 写作卡决定。
