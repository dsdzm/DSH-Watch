## 1. 扫码登录：把「翻开发者工具」这一步干掉

### 接口

| 步骤 | 请求 | 关键返回 |
|---|---|---|
| 申请 | `GET passport.bilibili.com/x/passport-login/web/qrcode/generate` | `data.url`（二维码内容）、`data.qrcode_key` |
| 轮询 | `GET .../qrcode/poll?qrcode_key=...` | `data.code`：0 成功 / 86101 未扫码 / 86090 已扫码待确认 / 86038 过期 |

**外层 `code` 永远是 0**，状态全在内层 `data.code` 里 —— 这是这一类接口最容易写错的地方，
拿外层判断会得到「一直是成功」的假象。

### 二维码怎么画

| 方案 | 问题 |
|---|---|
| `QRCodeWriter.encode(w, 512, 512)` | 内部按整数倍缩放，尺寸不合适就多白边或直接抛异常 |
| 先画 Bitmap 再 `Image` 缩放 | 圆屏 300px 上格线糊成灰块，手机扫不出来 |
| **`Encoder.encode` 拿模块矩阵 + Canvas 逐格画** | 硬边、任意尺寸、静区可控 ← 采用 |

静区固定 4 个模块（`cell = size / (n + 8)`）。B站 的扫码器对白边很敏感，切掉就识别失败。
二维码宽度取屏宽 74%：圆屏的内切圆只有边长的 0.707 倍，再大四角会被裁。

### 凭证落地

成功时 B站 在 `Set-Cookie` 里给一串键，只挑白名单：
`SESSDATA` / `bili_jct` / `DedeUserID` / `DedeUserID__ckMd5` / `sid` / `buvid3` / `buvid4`。

拿不到响应头时退回 `data.url` 的 query —— **不解码**：SESSDATA 本身是 URL 编码过的
（含 `%2C`），浏览器就是拿编码值当 Cookie 发的，解码后拼回去 B站 认不出来。

落 `SecureKeyStore`（Android Keystore），界面只显示「已登录 · 昵称」。
手填 Cookie 的入口保留 —— 公司网/代理环境下 passport 域名可能连不通，那时只能手填。

## 2. 评论风格：默认是条吃白饭的摸鱼大肥鱼

| 预设 | 提示词要点 | 典型长度 |
|---|---|---|
| `fish`（默认） | 躺平、蹭饭、爱自嘲摸鱼，夸得随意、吐槽不刻薄 | 15–60 字 |
| `serious` | 具体到某个论点或某处错误，带自己的经验/反例 | 40–150 字 |
| `deadpan` | 抽象玩梗、短促、不脏不引战 | 10–40 字 |
| `custom` | 用户自己写「像谁在说话」，原样交给模型 | 不限 |

### 为什么写在 `bili_status` 里而不是系统提示

系统提示每一轮都要付 token；风格只在真要发评论时才有用。
放进 `bili_status` 的返回值，等于「读一次、用一轮」。

### 闸门跟着风格走

`StyleGate` 只做四件事：长度 5–300、无链接、非纯表情、命中禁词表。

禁词表按风格取：

- **默认/认真/抽象**：通用 AI 腔 + 各自的黑名单（家人们、干货满满、一键三连…）
- **自定义**：只剩 AI 腔（「作为AI」「希望对你有帮助」）

原因很直接：用户写「像一个老工程师，说话直」，结果被别人的「家人们」黑名单拦住，
就是工具在替用户审美。

## 3. 后台跑得住

1.8 已经有前台服务 + 唤醒锁，但有两个洞：

| 洞 | 表现 | 1.9 的做法 |
|---|---|---|
| 通知永远写「正在生成」 | 刷一轮几十次调用，用户不知道在干什么 | 每次工具开始 `ACTION_UPDATE` 改第二行为「正在读字幕」这类动作 |
| 唤醒锁 15 分钟一次性 | 跑到第 16 分钟 CPU 睡，socket 读挂住 = 「跑一半停了」 | 每 8 分钟自动续 + 每次进度更新各续一次 |

外加「跑完通知我」：结束后发一条可点掉的普通通知（默认开）。
手表上最难受的不是慢，是不知道跑完没有。

生成本身一直在 `AppContainer.appScope` 里跑，Activity 销毁不打断 —— 这点 1.6 就已成立，
1.9 只是让它「可观测」。

## 4. 会接话：回复别人的回复

### 数据从哪来

`GET /x/msgfeed/reply`（消息中心「回复我的」，**必须登录**）：

```
data.items[]：
  user.nickname            谁
  item.source_content      他说了什么
  item.target_reply_content 我原来那条
  item.title / uri         哪个视频（uri 里带 BV 号）
  item.root_id             这栋楼的根评论
  item.source_id           他那条评论  ← 回复时当 parent
  item.business_id         1 = 视频评论
```

### 三个工具

| 工具 | 作用 |
|---|---|
| `bili_inbox` | 列「回复我的」，每条直接给出可复制的 `bili_reply bvid=… root=… parent=…` |
| `bili_thread` | 拉某栋楼：根评论 + 全部回复（带 rpid / mid） |
| `bili_reply` | 新增 `root` / `parent`；两个都不带就是顶层评论 |

### 楼中楼的口径

`/x/v2/reply/add` 里：

- `root` = 整栋楼的根评论 rpid
- `parent` = **被回复的那一条**的 rpid

只给 `parent` 不给 `root`，B站 会把回复挂到评论区顶层而不是对方那条下面 ——
表现就是「明明回复了，对方收不到通知」。所以代码里两个必须成对出现，缺一个直接报错。

### 判重键

从 `bvid` 改成 `bvid|root|parent`。否则在同一个视频底下回了 A 就不能再回 B。
老版本只记 `bvid` 的行仍然匹配顶层评论（root/parent 都是 0），不需要迁移。

## 5. 实测记录

| 项 | 结果 |
|---|---|
| 二维码生成 | ✅ 返回 `url` + 32 位 `qrcode_key` |
| 未扫码轮询 | ✅ 稳定 `86101 未扫码`，不误判 |
| 楼中楼 | ✅ 真实视频：根评论 + 2 条楼内回复，rpid 对得上 |
| `inbox` 匿名 | ✅ 返回 `-101 账号未登录`，工具层转成「去扫码登录」提示 |
| `me()` 匿名 | ✅ `loggedIn=false`，不抛异常 |
| 单测 | 561 项全绿（新增 6 项风格/闸门约束） |

`inbox` 的字段结构来自社区接口文档（`msgfeed/reply` 的 `items[].item.*`），
因为是登录态接口，没法用匿名探针验证；解析全部按「取不到就跳过该条」写，
最坏情况是列表偏少，不会崩。

## 6. 真机验收清单

1. 设置 → 刷B站 → 扫码登录：二维码清晰、手机能扫出来
2. 手机确认后 2 秒内跳回、显示「已登录 · 昵称」
3. 二维码静置 3 分钟 → 显示「二维码过期了」+ 重新生成
4. 评论风格切到「自定义」写一段，发一条预览，语气应跟着变
5. 让模型「刷一轮B站」，然后**立刻熄屏**；通知栏应逐步变成「正在读字幕」这类文案，
   10 分钟后抬腕仍在跑
6. 跑完收到「跑完了」通知
7. 在 B站 手机端回复自己的某条评论，再对手表说「看看谁回了我」：
   应列出对方的原话 + 你的原话，并给出 root/parent
8. 让它回一条：应弹确认，确认后手机上能看到在自己的评论下方

## 7. 已知限制

- `msgfeed/reply` 的翻页游标（`cursor.id` / `time`）暂未接，只取首页 20 条
- 二维码在小圆屏 + 强反光下有扫不出来的可能，这是物理限制，不是实现问题
- 评论风格只是「提示」，模型仍可能偶尔跑偏；`StyleGate` 只兜底明显套话
- `bili_inbox` 只能看视频评论的回复（`business_id=1`），动态/专栏的回复暂不处理
