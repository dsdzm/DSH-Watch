# DSH Watch 参赛视频方案

> 对应版本：v1.21.1（versionCode 65）
> 用途：B 站「AI 创造公开赛」投稿 + 项目主页首屏视频
> 核心主张：**电脑关了，它还在跑。**

---

## 一、先说结论

三条：

1. **不要和「手表遥控电脑」那类项目比功能数量**，比不过，也没必要。它们的强项是看会话、看工具调用、看子智能体，那是把电脑界面搬小。你的强项只有一句：**不需要电脑**。整条片子只讲这一句。
2. **不要用云端 AI 剪辑服务剪未发布的实机素材**。ChatCut、Oh My Cassette 这类 MCP 剪辑，剪辑能力在云端，素材要上传。项目还没正式发布，实机画面里有你的 API Key、会话内容、设备信息。**本地优先**。
3. **不要做 4 分钟**。对方那条是 4:31，完播率会很惨。比赛片控制在 90 秒，前 4 秒必须出现「电脑合上」这个动作。

### 推荐组合（务实版）

```
拍素材 → BaoCut 粗剪 + 自动字幕 → 导出 → 剪映精修（字幕样式、音效、封面）
                ↑
        分镜固定后，用 pyJianYingDraft 生成草稿，省掉手工拖时间线
```

理由：

- **BaoCut** 自带 Whisper，中文识别够用，去静音/去口癖对 90 秒片是刚需；时间线可编辑，不是一次性出片。
- **pyJianYingDraft** 解决"每次改脚本都要重新拖一遍时间线"的问题。分镜表定稿后，用 Python 把 9 个镜头按秒数铺进草稿，剪映打开就能改。
- **video-shotcraft** 只用来做 0-2 秒的片头和结尾卡片，Remotion 出 1080p，透明背景叠在实拍上。

如果只想快点出片：**剪映专业版手动剪 + 自动字幕**，90 秒的片子两小时能搞定。上面那套是给"要反复改 5 版"准备的。

## 三、视频策略

### 一句话主张

> 别人的手表是遥控器，这块手表是主机。

### 三条不做

1. **不出现"我也做了一个 DSH 手表端"**——一开口就把自己放进别人的赛道。
2. **不念参数表**。52 个工具、8.7MB 这些数字用字幕打，不要口播。
3. **不演示"看 AI 干活"**。那是遥控方案的主场。只演示"AI 在这块表上干活"。

### 差异化镜头（只有你能拍）

| 镜头 | 为什么别人拍不了 |
|---|---|
| 笔记本合上，手表继续输出 | 遥控方案合盖就断连 |
| 手表上弹 Shizuku 审批，写明用途和命令 | 遥控方案没有本机提权 |
| AI 自己点开设置调亮度 | 遥控方案只能看，不能动这台设备 |
| 安装包 8.7MB，单 APK | 遥控方案要装 exe + APK，且电脑必须开机 |

### 简介

```
电脑上跑 Agent，人就得守在旁边。我把引擎直接塞进了手表。

【它是什么】
一块 Android 手表上的独立 Agent 客户端。模型走云端 API，工具循环在表盘上跑。
不连电脑，不需要电脑端程序，一个 8.7MB 的 APK。

【它能干什么】
· 对话、流式输出、思维链折叠、Markdown / 代码 / 表格渲染
· 52 个工具：读写文件、跑脚本、搜网页、云编译、闹钟日程、B 站
· 工具每一轮都全量下发，模型不用先查目录再取 —— 少一轮就少一次卡住的机会
· 接 Shizuku 跑 adb：每条命令必须先写用途，你确认才执行
· 删除系统文件这类操作标红警告，两次确认，第一次不执行任何东西
· 无障碍设备操控：读屏、点按、翻页、改设置，随时可按停
· 会话本地保存、切模型、看 token 用量

【它不是什么】
不是"在手表上看电脑上的会话"。那种方案电脑必须开着。
这块表自己就是主机。

【怎么装】
GitHub Releases 下载 APK，adb install 或者传进手表点开安装。
需要自己填一个 OpenAI 兼容的 API Key（DeepSeek / 中转站 / 本地 Ollama 都行）。

开源地址：https://github.com/dsdzm/DSH-Watch
GPL-3.0，欢迎提 issue。

#B站AI创造公开赛
```

### C. 录屏参数

```bash
# 先看分辨率，466x466 / 480x480 / 454x454 都可能
adb shell wm size

# 按实际分辨率录，码率给足，否则小字会糊
adb shell screenrecord --size 466x466 --bit-rate 8000000 --time-limit 180 /sdcard/demo.mp4

# 拉回电脑
adb pull /sdcard/demo.mp4
```

录之前：

- 关通知、开勿扰，电量 > 50%，亮度最高，关闭自动亮度
- 清掉测试会话，别让无关项目名进画面
- API Key 页面不要录；如果录到，后期打码
- 手表录屏是方的，圆屏机器后期要加圆形遮罩，否则四角是黑的

### D. 拍摄注意事项

1. **表盘反光**是这类片子最大的杀手。手机镜头和表盘成 30-45°，别正对；有偏振镜就上。
2. **不要用相机自动曝光**。表盘是自发光的，自动曝光会来回跳。锁定曝光，宁可暗一点，后期提。
3. **口播单独录**，不要现场收音。90 秒的片子，音质差比画质差更劝退。
4. **同一机位拍 3 条**，手部动作很难一次到位。
5. 素材命名：`A6_screenrecord_task_v1.mp4`，按上面的编号，后期对轴不会乱。

## 八、后期流水线

### 1. 统一素材

```bash
# 实拍统一到 1080p25，音频 48k
ffmpeg -i A2_wrist.mp4 -vf "scale=1920:1080:force_original_aspect_ratio=decrease,pad=1920:1080:(ow-iw)/2:(oh-ih)/2,fps=25" \
       -c:v libx264 -crf 18 -preset slow -c:a aac -ar 48000 -b:a 192k A2_norm.mp4

# 录屏放大 2 倍并加圆角遮罩（方屏机器可跳过遮罩）
ffmpeg -i A6_screenrecord.mp4 -vf "scale=932:932:flags=lanczos" -c:v libx264 -crf 16 A6_big.mp4
```

### 2. 粗剪

BaoCut 导入全部素材 → 按第四章时间轴铺 → 自动字幕 → 导出 XML/工程。

### 3. 精剪

剪映专业版：字幕样式统一（思源黑体 Bold，白字 + 2px 黑描边）、关键节点加音效（合盖、点击、审批弹出）、BGM 压到 -22dB。

### 4. 导出

```
H.264 / 1080p / 25fps / 12Mbps / AAC 192kbps
```

B 站上传后不要立刻发布，等审核通过再定时；封面单独上传，别用自动截帧。

### 5. 如果想批量改版

分镜定稿后，用 `pyJianYingDraft` 按秒数生成草稿：新建工程 → 加视频轨 → 把第四章表格里的「时间」列直接当 `start` / `duration` 逐段写进去。

具体 API 以仓库 README 为准（版本迭代较快，这里不贴易过期的代码）。收益是：改一版脚本 = 改表格里几个数字，不用重新拖时间线。
