# 声明式插件

手表上没有 Node。DSH 官方插件是 Cordis 的 npm 包，`apply(ctx)` 里能拿到 `ctx.fs`、
子进程和工具注册表 —— 这套东西在 Android 手表上跑不起来，硬塞一个 libnode 会把
APK 从 8 MB 推到 200 MB，还得逐个补 sqlite、sandbox、ripgrep 的移植。

所以这里的插件是**一份 JSON 声明**：它能改模型看到什么、能碰什么，
但碰不到设备本身。

## 它能改两件事

| 段 | 改什么 | 对应 DSH 生态里的哪类插件 |
|---|---|---|
| `prompt` | 模型看到的话（身份、尾部锚点、按模型切规则） | 人格 / 破甲 / 措辞类 |
| `tools` | 模型能碰到的工具面与确认强度 | dsh-purge 那类「任务不再被打断」的 |

## 放在哪

两条路，二选一即可：

**目录**（适合一次放好几份）

```
工作空间/
└─ plugins/
   ├─ terse.json
   └─ focus-offline.json
```

设置 → 插件 → 重新扫描插件目录。扫描是覆盖式的：删掉文件再扫一次，插件就没了。

**导入**（适合从别人那里拿一份）

设置 → 插件 → 导入，四条路：

| 入口 | 用什么 |
|---|---|
| 选择文件 | `.tgz` / `.tar.gz` / `.json`，系统文件选择器直接挑 |
| 从工作空间选 | 包已经放进工作空间，直接点（手表没有文件管理器时用这条） |
| 剪贴板 | 一段 JSON 文本 |
| 链接 | 一条 raw 地址 |

导入前会跑一遍完整校验，过了才落盘；同名 id 重复导入是覆盖，不会堆两层。

两条路的配额各 12 个，单个清单 8 000 字符（tgz 里解出来的清单同样受这个限制，
包本身上限 2 MB）。导入的插件在文件系统里没有对应文件，
所以单独给了「移除导入的插件」。

## 字段

```json
{
  "schema": 2,
  "id": "dsh-plugin-example",
  "name": "示例",
  "description": "一句话说明它改了什么",
  "version": "1.0.0",
  "author": "谁写的",
  "prompt": {
    "identity": "替换用的身份段",
    "append": "追加到系统提示末尾的规则",
    "when": { "model": "deepseek-*" }
  },
  "tools": {
    "hide": ["web_search"],
    "confirm": ["write_file"]
  }
}
```

| 字段 | 说明 |
|---|---|
| `schema` | 写 `2`。老清单写 `1` 或不写，照常能用 |
| `id` | 必填，`dsh-plugin-` 开头，前缀后面再写 3–47 个字符，不能和内置插件重名 |
| `name` | 设置页显示的名字，最多 40 字 |
| `description` | 一句话说明它改了什么，最多 120 字 |
| `prompt.identity` | 前置的身份段。**不删除**内置身份，而是在它前面加一段并声明优先 |
| `prompt.append` | 尾部锚点。模型对末尾指令的服从度更高，长期规则放这里 |
| `prompt.when.model` | 只在模型名匹配时生效，支持 `*`，留空表示全部 |
| `tools.hide` | 从模型眼前拿掉这些工具，最多 64 个 |
| `tools.only` | 只留这些，其余全下架。**与 `hide` 互斥** |
| `tools.confirm` | 这些工具改成每次确认 |
| `tools.when.model` | 同上，只在模型匹配时生效 |

`prompt` 和 `tools` 至少写一个，两个都空等于装了个寂寞，会被拒收。

变量：`{{model}}` `{{provider}}` `{{today}}` `{{weekday}}`。认不出的变量原样保留，
不会报错。

## 隐藏是执行层拦截

`hide` / `only` 不只是「提示里不提这个工具」。模型完全可能在上文里见过工具名
（换过插件、换过模式），照样能拼出一个调用 —— 所以执行前还有一道硬拦，
命中就回一条「该工具已被插件停用」。

`only` 写错名字时按「没写」处理：如果白名单里一个都对不上现有工具，
这次不限制并提示你检查。工具名有四十多个，少打一个字母是常事，
照字面执行的结果会是所有工具消失 —— 那看起来像模型变笨，不像插件写错。

多份插件同时开时：

- `hide` 取并集（谁禁都算禁）；
- `only` 取**交集**。两份白名单各写一份，合起来必须更窄 ——
  取并集等于「两份都在收紧，合起来反而放宽」；
- `confirm` 取并集（任何一个要求确认，就得确认）。

## 为什么只能收紧

dsh-purge 那类项目会顺带放宽终端命令、文件操作的确认，减少任务中断。
这里**只做加严，不做放宽**，原因不是技术做不到：

- 插件只能**声明它需要什么**，不能**声明什么可以放过**；
- `autoApprove` / `tools.allow` / `approval` / `sandbox` 这些键一旦出现，
  整份清单当场拒收并说明原因 —— 静默忽略会让用户以为免确认生效了；
- `run_script:shell`、`adb_shell`、`cloud_build` 永远逐次确认，任何清单都改不了；
- 想少点弹窗，去「AI 能力 → 审批」里自己调，那是用户的选择，不是插件的。

插件是用户从网上下载、自己都不会逐字读完的文本。如果它能放宽审批，
「装一个插件」就等于「把设备控制权交给一个陌生人的 JSON」。
而收紧永远不会害人 —— 最差是模型干不了活，用户一眼就能看出来。

## dsh-purge 的哪些部分能对上

| dsh-purge | 这里 | 状态 |
|---|---|---|
| 系统提示词注入 / 替换 | `prompt.identity` | 支持 |
| 尾部锚点（1.1.84） | `prompt.append` | 支持 |
| 按模型切规则集 | `prompt.when.model` | 支持 |
| 减少打断（不反复确认） | —— | 有意不做，见上一节 |
| 隐藏无关工具、收窄工具面 | `tools.hide` / `tools.only` | 支持 |
| 关键步骤强制确认 | `tools.confirm` | 支持 |
| AGENTS.md / CLAUDE.md 管理 | 写进工作空间，用 `read_file` 读 | 不适用 |
| 沙箱策略 | 手表无沙箱 | 不适用 |
| 二进制补丁 | 宿主是自己的，不需要 | 不适用 |

## 打成 tgz 分发

有人想把插件传给别人，别让他复制一段 JSON —— 打个包，一个文件就够：

```
my-plugin/
└─ package/
   ├─ dsh-plugin.json     ← 必须有，就是上面那份清单
   ├─ package.json        ← 可选
   └─ README.md           ← 可选
```

```bash
tar czf dsh-plugin-my-1.0.0.tgz package/
```

`npm pack` 出来的文件结构正好也是这样，可以直接拿 `npm pack` 打。
包里的清单文件名必须是 `dsh-plugin.json`，位置不限（会在所有条目里找，
有多份时取路径最浅的那份）。

**官方 Cordis 插件装不了**，这不是没做：那种包里是 `package.json` + JS，
靠 `apply(ctx)` 在 Node 里跑。手表上没有 Node 运行时。导入时会明确告诉
用户「这是 Cordis 插件」，而不是静默失败。

## 安装

最省事的四种方式：

1. **选文件** —— 设置 → 插件 → 导入 → 选择文件，挑 `.tgz` 或 `.json`；
2. **导入链接** —— 同上去「从链接导入」，粘一条 raw 地址；
3. **让助手自己写** —— 「把 docs/plugins/terse.json 的内容写到工作空间 plugins/ 目录」；
4. **adb**

```bash
adb push docs/plugins/terse.json /sdcard/Download/
# 再在 App 的文件页里移到 workspace/plugins/
```

装完进设置 → 插件，开关出现在列表里。声明式插件默认关闭 ——
它改的是模型的自我认知和工具面，这个决定应该由你按。
